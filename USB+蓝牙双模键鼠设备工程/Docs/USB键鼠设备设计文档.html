1 功能描述

本设备是一个 USB 全速复合 HID 设备，并同时通过板载 RDA5876 提供蓝牙 HID 键盘 + 鼠标。两条链路共用同一套板载按键与摇杆，由自动选路决定输入往哪边发（见第 10 章）。USB 侧插入电脑后，Windows 会枚举出三个彼此独立的 HID 接口，各自使用系统自带驱动，不需要安装任何驱动程序：

接口功能端点电脑侧表现
Interface 0标准键盘（Boot Keyboard）中断 IN 0x81「HID 键盘设备」，Caps Lock / Num Lock / 空格 / 回车
Interface 1标准鼠标（Boot Mouse）中断 IN 0x82「HID 鼠标设备」，光标、滚轮、左右键
Interface 2自定义 HID（Vendor Defined）中断 IN 0x83 / OUT 0x03「HID-compliant device」，供上位机专用

已实现的板载功能

  • 鼠标：左摇杆控制光标 X/Y 相对位移（先按板上 90° 安装做旋转修正，再用「死区 + 平方曲线」控制速度）；A / B / LF 分别对应左键 / 右键 / 中键；右摇杆控制滚轮（每 100ms 一格，防止疯狂滚动）。UP / DN 不再控制滚轮。
  • 键盘：X 键发送 Caps Lock（HID 键码 0x39），Y 键发送 Num Lock（0x53），UP 键发送空格 Space（0x2C），DN 键发送回车 Enter（0x28，主键盘回车，不是小键盘的 0x58）；四个键都采用「按下 30ms 后自动补发释放报告」的点按方式，避免 Windows 认为按键一直按着而反复切换或连续输入。
  • 锁定指示灯：主机通过 SET_REPORT 下发键盘 LED 状态后，板载 RGB 灯的绿灯表示 Num Lock、红灯表示 Caps Lock，与电脑实际锁定状态同步，而不是「按一下闪一下」。
  • 自定义 HID 上行：8 个板载按键组成位图，状态变化时立即上传，平时 1 秒一次心跳，便于上位机判断设备在线。
  • 自定义 HID 下行：接收上位机的 RGB 命令，直接设置板载 RGB 三路亮度（0~100）。
V2.0 双模：同一套输入经主循环里的 UsbHid_Task() 与 BT_Task() 两条链路输出。USB 枚举完成时蓝牙只维持链路、不发输入报告，避免同一台电脑上出现双倍光标 / 重复按键；USB 未挂载时才由蓝牙发送键鼠报告。详见第 10 章。
主函数 User/main.c 运行 USB 键鼠 + 蓝牙键鼠两条链路；把 ENABLE_BLUETOOTH 改成 0 即可退回纯 USB 单模。USB 声卡、Codec / I²S、CDC 虚拟串口仍不参与启动。

2 设计思路

2.1 为什么用三个独立接口，而不是一个接口加 Report ID

键盘和鼠标也可以合并在一个 HID 接口里，用 Report ID 区分。但那样 BIOS、Windows 安装界面、PE 等只有简易 HID 驱动的环境往往只识别第一个 Report，兼容性差。拆成三个接口后，Windows 会把键盘、鼠标分别挂到系统自带驱动上，自定义接口单独留给上位机，行为最稳定，也正好对应考核「复合设备」的要求。

2.2 为什么键盘 / 鼠标声明 Boot 协议，自定义接口不声明

键盘接口 SubClass=1, Protocol=1、鼠标接口 SubClass=1, Protocol=2，即 USB HID 引导协议，无需完整 HID 报告解析即可使用。自定义接口填 0/0，系统只按报告描述符处理，不会把自定义数据误当成键盘输入。

2.3 报告描述符由模板宏生成，长度由编译期断言保证

键盘 65 字节、鼠标 77 字节、自定义 27 字节。配置描述符里的 wDescriptorLength 必须与数组实际长度一致，写错一个字节主机就会在枚举阶段拿到残缺报告。因此：

TU_VERIFY_STATIC(sizeof(desc_kbd)      == HID_DESC_LEN_KEYBOARD, "...");
TU_VERIFY_STATIC(sizeof(desc_mouse)    == HID_DESC_LEN_MOUSE,    "...");
TU_VERIFY_STATIC(sizeof(desc_custom)   == HID_DESC_LEN_CUSTOM,   "...");
TU_VERIFY_STATIC(sizeof(desc_configuration) == CONFIG_TOTAL_LEN,  "...");   /* 91 字节 */

任何一处长度对不上，编译期就会报错，而不是等到插上 USB 才发现枚举失败。

2.4 STM32F103 的 PMA 预算

F103 的 USB 包存储区只有 512 字节，三个接口共四个端点，必须提前算清楚：

用途字节
BTABLE（8 个端点偏移表）64
EP0 IN + OUT（控制传输，各 64）128
EP1 IN 键盘64
EP2 IN 鼠标64
EP3 IN + OUT 自定义 HID128
合计448 ≤ 512（余 64）

2.5 主循环绝不阻塞

tud_task() 负责枚举、控制传输与端点事件，任何一次长时间阻塞都会让主机认为设备失联。因此所有延时都改成基于 TIM4 的 1ms 时基做「到点判断」，10ms 扫描一次输入，不做 while 死等。D+ 上拉也刻意延后：上电先把 PA12 输出低让主机看不到设备，等按键、摇杆、RGB、协议栈都初始化完，再切成复用功能，保证是一次干净的插入。

左摇杆ADC光标 X/Y 相对位移（旋转修正 + 平方速度曲线）—
右摇杆ADC滚轮（旋转后取「上」分量，阈值 ±12000，100ms 一格）—
方向与速度校准：板上两个摇杆是旋转 90° 安装的，物理「上」落在 X 通道。joystick.c 用 JOY_ROTATE_90 修正过，usb_hid.c 的 joy_rotate() 用 USB_JOY_AXIS_ROTATE=1 做同样修正；否则把 LX 当水平位移，推「上」就会变成光标左移。速度采用「死区 3000 + 平方曲线 + 每 10ms 上限 USB_JOY_MOUSE_MAX=12 像素」：中心附近只有 1~2 像素/报告，满偏约 1200 像素/秒（可继续调到 16）；旧版线性除以 480 相当于约 6800 像素/秒，几乎无法瞄准。实测某个方向相反，把 USB_MOUSE_INVERT_X / USB_MOUSE_INVERT_Y / USB_WHEEL_INVERT 改成 1；太快调小 USB_JOY_MOUSE_MAX，中心漂移调大 USB_JOY_DEADZONE；安装角度不同则依次试 USB_JOY_AXIS_ROTATE 的 0 / 2 / 3。

7 自定义 HID 通信协议

厂商自定义 Usage Page 0xFF00，输入 / 输出各 8 字节，无 Report ID。上位机应只打开 VID 0xCafe / PID 0x4004 的第三个 HID 接口，不要误开系统键盘或鼠标接口。

7.1 设备 → PC（输入报告）

字节 0   按键位图：0 = 松开，1 = 按下（bit0=A … bit7=RG）
字节 1   报告序号，每次上传 +1，便于上位机判断有没有丢包
字节 2~7 保留，固定 0

示例  05 1C 00 00 00 00 00 00
      └─ bit0+bit2 = A 与 X 同时按下，序号 0x1C

触发条件：按键位图发生变化时立即上传；无变化时每 1000ms 上传一次心跳。

7.2 PC → 设备（输出报告）

命令 0x01  SET_RGB：[0]=0x01 [1]=R [2]=G [3]=B [4..7]=0
                     R/G/B 范围 0~100（超过会被限幅），直接驱动板载 RGB
命令 0x02  GET_STATUS：协议预留，当前固件收到后只打印一行日志，不回数据

示例  01 64 32 00 00 00 00 00   → 红 100%、绿 50%、蓝 0%（橙色）
键盘 LED 状态与 RGB 命令共用同一组 PC7/PC8/PC9 引脚。当前策略是键盘锁定状态优先：收到 LED 输出报告时会按 Num/Caps Lock 状态重设绿灯和红灯（亮度 60），因此上位机设置的红/绿分量可能被覆盖。若后续需要两者完全独立，可在应用层增加「RGB 已被上位机接管」标志，让 LED 回调只改蓝灯或专用指示灯。

10 双模扩展：蓝牙键鼠

10.1 为什么能共存

两套协议栈占用的外设互不重叠，Flash 256KB / RAM 48KB 也放得下合并后的代码（Code≈55KB）。合并时真正要处理的只有三件事：TIM4 时基只能初始化一次（hal_time_ms() 由 usb_hid.c 提供，不能再编 usb_audio.c）；RGB 驱动在 tim2.c / tim3.c 中二选一（本工程用 tim2 软件 PWM）；蓝牙初始化阻塞期间必须让 USB 保持在「未插入」状态。

资源USB 链路蓝牙链路结论
引脚PA11 / PA12（USB DP/DM）PA2 / PA3（USART2）、PA8（TIM1 32.768kHz）、PC12（复位 / LDO）无重叠
定时器TIM4 1ms 时基、TIM2 软件 PWMTIM1 输出参考时钟共用 TIM4，其余独立
中断USB LP/HP（优先级 2）、TIM4（3）USART2 中断接收，1024B 环形缓冲主循环不阻塞即可
Flash代码区末页 0x0803F800 存 Link Key约 55KB，离末页很远
共用输入8 按键 EXTI、双摇杆 ADC PA4~PA7、USART1 921600 日志、hal_time_ms()同一套驱动

10.2 蓝牙 HID 设备形态

原蓝牙工程是游戏手柄（SDP 642 字节 / 手柄描述符 306 字节）。改成键鼠时只替换 SDP 里的 HIDReportDescriptor，其余属性、PnP 记录、两条 ProtocolDescriptorList 骨架一个字节没动——历史上整条重写 SDP 记录（481 / 513 字节变体）都导致 Windows 连不上，保留已验证的框架风险最小。

SDP AttributeList : 642 -> 455 字节
HIDReportDescriptor: 306 -> 119 字节 = 键盘 65B + 鼠标 54B
HIDDeviceSubclass : 0x40 (Keyboard) -> 0xC0 (Combo keyboard/pointing)
设备名 / CoD      : STM32 BT KeyMouse / 0x0005C0

长度对账（L = 描述符长度）：
  0x26 文本串      = L
  内层 0x36 序列   = 5 + L
  外层 0x36 序列   = 8 + L
  记录2 0x36 序列  = 207 + L
  数组总长         = 336 + L      （L = 119 -> 455）

V2.1 追加的等长替换（不动任何长度字段）：
  ServiceName   : "Xbox Bluetooth Gamepad" -> "STM32 HID KeyMouse Dev"（同为 22 字节）
  PnP VendorID  : 0x045E (Microsoft) -> 0x1234
  PnP ProductID : 0x02E0 (Xbox 手柄) -> 0x4004（与 USB 侧一致）

后两项很关键：原 SDP 记录抄自 Xbox 手柄抓包，Windows 看到 0x045E/0x02E0 加上服务名里带「Gamepad」会沿用缓存的游戏控制器驱动，即使描述符已换成键盘/鼠标也不会加载键鼠驱动。等长替换既不破坏长度字段，也能让主机重新做一次驱动匹配。

10.3 报告格式

两个 Application Collection 靠 Report ID 区分，HIDP 输入报告统一是 0xA1 + ID + 数据：

ID 1 键盘（10 字节）：A1 01 [修饰键][保留][6 键码]
ID 2 鼠标（ 6 字节）：A1 02 [按键位][X][Y][滚轮]

设备每 20ms 采样一次：键盘只在按键位图变化时发（松手发全 0 报告释放），鼠标在位移 / 滚轮非零或按键变化时发。摇杆换算沿用 USB 侧的「90° 旋转 + 死区 3000 + 平方曲线 + 上限 12」，USB_JOY_* 与 BT_JOY_* 两套宏要同步修改。SET_REPORT（键盘 LED）目前只回成功、不解析，所以纯蓝牙模式下指示灯不跟随锁定状态；GET_REPORT 由原来的 NAK 改为回一份空 DATA 报告，更贴合蓝牙键盘驱动。

V2.1 HIDP 协议修正：hidp_control_rsp() 原先在 GET_PROTOCOL 回 0xA1，而 HIDP DATA 头低 4 位里 1 = Boot 协议、0 = Report 协议，等于告诉主机「按 boot 格式解析」。主机会把报告里的 Report ID 0x01 当成修饰键 / 按键位，键鼠全部错乱——正是「连得上但用不了」。现在改为如实回报当前协议，GET_IDLE 也补上了规范要求的数据字节。

V2.2 双协议支持（关键修复）：上一版收到 SET_PROTOCOL(Boot) 时回 0x04 ERR_UNSUPPORTED_REQ 拒绝，这是错的。Windows 的蓝牙键盘驱动 hidbth 为了让键盘在 BIOS / 登录界面可用，几乎一定会把设备切到 Boot 协议；被拒绝后部分版本会判定「设备不符合 HID 规范」，干脆不加载键鼠驱动——于是蓝牙连得上、设备列表里也有，但按键和摇杆完全没反应。现在改为记录 g_bt_hid_protocol 并按协议换报告格式：

Report 协议（proto=0）  键盘 A1 01 + 8B（10 字节）   鼠标 A1 02 + 4B（6 字节）
Boot   协议（proto=1）  键盘 A1    + 8B（ 9 字节）   鼠标 A1    + 3B（4 字节，无滚轮）

另外在 HID Interrupt 通道刚建立时主动补发一帧「全松开、无位移」报告：部分 Windows 版本要收到第一帧输入报告才会把这个蓝牙 HID 设备真正注册进键鼠堆栈，在那之前按键没有任何反应。串口会看到 [hid] SET_PROTOCOL -> Boot，这是正常且必须的。

10.4 自动选路

BT_Task() 发报告前调用 UsbHid_IsMounted()（内部即 tud_mounted()）。USB 已挂载：输入只走 USB，蓝牙链路照常保持、照常跑 L2CAP/SDP，但不发输入报告；USB 未挂载：输入走蓝牙键鼠。串口在切换时打印 [mux] input -> USB / BLUETOOTH。这样两条链路同时连同一台电脑时不会出现双倍光标或重复按键。
供电约束：若板子只靠这根 USB 线供电，拔线会同时断电，蓝牙链路也就不存在了。要验证「纯蓝牙」必须给板子独立供电（ST-Link、外部 5V 或电池）。

10.5 上板验证要点与已知风险

本章改动只做了完整编译验证（0 Error），尚未上板抓包验证。若配对后显示「无可用服务」或只认出键盘 / 鼠标之一，按此顺序排查：① SDP 四个长度字段与数组总长是否一致；② HIDDeviceSubclass=0xC0 是否被驱动接受；③ hidp_control_rsp() 的 GET_REPORT 应答格式；④ 设备管理器里的蓝牙设备类别（CoD）。V2.1 修正了 HIDP 协议应答与 SDP 设备标识，V2.2 补上 Boot 协议支持与首帧报告，具体排查顺序见 10.6；回退方式见 Docs/README.md 第 11 节。

10.6 「电脑能连上蓝牙，但键鼠没反应」排查清单

  1. 先删掉 Windows 里的旧配对（最常见）。这台电脑之前配对过蓝牙游戏手柄，BD_ADDR 没变，Windows 会沿用缓存的设备类型与驱动。设置 → 蓝牙和其他设备 →「移除设备」；板子上电时按住 A 键清掉 Flash 绑定（串口打印 [bond] CLEARED）；重新搜索配对。
  2. 确认 USB 数据线没插在电脑上。只要 USB 枚举成功，自动选路就故意不发蓝牙报告。验证纯蓝牙要用「只供电、不接 D+/D−」的线（贴住 A 口中间两触点，或买充电专用线）接电脑 / 充电头。V2.2 起 BT_FORCE_REPORT 默认已设为 1（强制发），这一条暂时不挡人；蓝牙确认可用后要改回 0，否则同一台电脑会双倍输入。
  3. 读状态行。V2.2 起每 2 秒打印一次，字段变多了：[bt] st=3 ch=111 usb=0 proto=1 rpt=128 t=15320 drop=0。st 0=初始化 1=可发现 2=已连接 3=HID 就绪；ch 依次是 SDP / HID-Control / HID-Interrupt；usb 主机是否枚举成功；proto 0=Report、1=Boot；rpt 已发报告数；t 连接时长；drop 串口丢字节。
    rpt 一直不涨 = 报告没发出去；ch=110 = HID Interrupt 没开，主机没认出 HID 设备；ch=100 = 只开了 SDP；ch=000 = 主机没来开通道；反复出现 [bt] init=OK 从头开始 = 板子被断电重启。
  4. 看设备管理器。应出现「蓝牙 HID 键盘设备」与「HID 鼠标」，不能是游戏控制器或带黄色感叹号；V2.1 已把服务名和 PnP VID/PID 从 Xbox 手柄改成中性标识，就是为了触发重新匹配。
  5. 看 HIDP 日志。出现 [hid] SET_PROTOCOL -> Boot 是正常且必须的：主机切到 Boot 协议后，固件会自动改发「无 Report ID」的 9 字节键盘 / 4 字节鼠标报告。没有这行说明主机停在 Report 协议，同样可用。若 [hid] 一条都没有，说明主机还没打开 HID Control 通道。
  6. 排除供电干扰。充电宝轻载自动关机（板子 5V 侧仅 30~60mA，低于常见 50~80mA 阈值）会让板子每隔几秒断电重启，串口反复从头打印启动信息，看起来像「连上一会儿就掉」。改用电脑 USB 口 / 5V 充电头配充电专用线，或让充电宝进小电流模式、并 47Ω/1W 假负载。
本节依据的是静态代码审查与编译验证，尚未上板抓包。若按清单走完仍不生效，请把开机到配对完成的完整串口日志（921600 8N1）发回，重点看 [sdp]、[l2]、[hid] CTRL 三类行。
