# 自定义 HID 上位机（民展考核 · 第 3 项）

对应考核标准第 3 项「上位机与自定义 HID 双向交互」：

- **下位机 → 上位机**：8 个板载按键的实时状态（1 字节位图 + 1 字节序号）
- **上位机 → 下位机**：RGB 三通道亮度（各 0~100）

固件工程：`D:\minzhan\考核项目\USB鼠键设备`（USB 三接口复合设备：键盘 / 鼠标 / 自定义 HID）

---

## 一、运行环境

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11 x64 |
| Qt | 6.12.0 MinGW 64-bit（Qt Creator 自带） |
| CMake | 3.16 及以上 |
| 第三方库 | **无**。只用 Windows 原生 `SetupAPI` + `hid.dll` + `hidparse.dll` |

不引入 hidapi / libusb 的原因：MinGW 自带 HID 导入库，直接调 Win32 API 最轻，答辩时也能逐层讲清楚枚举、打开、读、写分别调了哪个函数。

## 二、编译

### Qt Creator（推荐）

1. 打开 `CMakeLists.txt`
2. 套件选 **Desktop Qt 6.12.0 MinGW 64-bit**
3. 直接构建

> 若之前构建过：修改了 `CMakeLists.txt`（新增 `hidparse` 链接库）后，Qt Creator 会提示重新运行 CMake，点「是」即可；也可以 `构建 → 执行 CMake`。

### 命令行

```bat
set PATH=D:\QT\Tools\mingw1310_64\bin;D:\QT\6.12.0\mingw_64\bin;%PATH%
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_PREFIX_PATH=D:/QT/6.12.0/mingw_64
cmake --build build -j4
```

产物：`build\shujianffuhe.exe`（只能在本机 Qt 环境里跑，需要 Qt 的 PATH）

### 一键打包（推荐给演示 / 答辩）

```bat
deploy.bat
```

双击即可。它会做四件事：配置 Release → 编译 → 把 exe 复制到 `dist\` → 用 `windeployqt` 把 Qt 运行库一起部署进 `dist\`。

产物：**`dist\shujianffuhe.exe`**，约 300 KB，同目录带着全部依赖 DLL，**不依赖 Qt Creator、不依赖 PATH，可以直接拷到别的电脑双击运行**。

> 为什么单独建 `dist`：`build\Release\shujianffuhe.exe` 会在每次重新链接时被删掉再写入，如果那一刻正好在资源管理器里刷新，会看到 exe“不见了”；而且 exe 正在运行时也无法被覆盖。`dist` 是稳定的发布副本，编译不会动它。

## 三、协议（与固件严格一致）

### 设备识别

| 项 | 值 |
|---|---|
| VID | `0xCafe` |
| PID | `0x4004` |
| 自定义接口 | UsagePage `0xFF00`，Usage `0x01` |
| 报告长度 | 输入 8 字节、输出 8 字节（描述符里无 Report ID） |

Windows HID API 的缓冲区首字节固定是 **Report ID**，本设备没有 Report ID 所以填 `0`，因此实际读写都是 **9 字节**。

### 输入报告（板子 → 上位机）

| 字节 | 含义 |
|---|---|
| 0 | Report ID = `0x00`（占位，不参与协议） |
| 1 | 按键位图：bit0=A，bit1=B，bit2=X，bit3=Y，bit4=UP，bit5=DN，bit6=LF，bit7=RG |
| 2 | 序号，每发一帧加 1，用于丢帧统计 |
| 3 | 电脑锁定状态：bit0 = NumLock，bit1 = CapsLock（旧固件无此字节，读作 0） |
| 4~8 | 保留，固定 0 |

位图按 **1 = 按下** 解释。固件 `key.h` 里 `KEY_A=1 … KEY_RG=8`，`bm |= 1 << (k - KEY_A)`，与上表完全对应。

第 3 字节的锁定状态来自**键盘 OUT 报告**（`tud_hid_set_report_cb` 里的 LED 字节），所以：
按电脑键盘的 Caps Lock、按板载 X 键，两者都会让这一位变化 —— 上位机不用去抢键盘接口，也能显示真实的锁定状态。

> 注意区分两个"灯"：板载红/绿灯跟的是**系统锁定状态**（键盘 LED 报告），上位机左侧 8 个圆灯跟的是**板载按键物理通断**（自定义 HID 位图）。按电脑键盘只会改变前者。

### 输出报告（上位机 → 板子）

| 字节 | 含义 |
|---|---|
| 0 | Report ID = `0x00` |
| 1 | 命令：`0x01` 设置 RGB / `0x02` 查询状态 |
| 2 | R，0~100 |
| 3 | G，0~100 |
| 4 | B，0~100 |
| 5~8 | 保留，固定 0 |

RGB 用 0~100 而不是 0~255：固件侧直接按百分比算 PWM 占空比，避免再做一次缩放。

### 按键功能对照

| 位 | 丝印 | 在 USB 键鼠里的功能 |
|---|---|---|
| bit0 | A | 鼠标左键 |
| bit1 | B | 鼠标右键 |
| bit2 | X | Caps Lock |
| bit3 | Y | Num Lock |
| bit4 | UP | 空格 |
| bit5 | DN | 回车 |
| bit6 | LF | 鼠标中键（滚轮按下） |
| bit7 | RG | 仅自定义 HID 上报，无键鼠映射 |

- **按键灯**：按下变实心（鼠标三键用蓝色，锁定键用橙色，字符键用绿色），右侧显示累计按下次数
- **丢帧统计**：用输入报告的序号做差，能直观看出 USB 链路是否丢帧
- **心跳**：2.5 秒内没收到报告就标红，说明固件停发或链路断了

## 五、操作步骤

1. **烧录固件**（`Project.hex`），用 USB 线把板子插到电脑
2. 设备管理器应出现「人体学输入设备」下的键盘、鼠标，以及一个自定义 HID
3. 打开上位机 → 点 **刷新设备**，下拉框出现类似
   `STM32 HID 0xCAFE:0x4004  UP:FF00 U:01  IN:9 OUT:9`
4. 点 **连接**，状态变绿
5. 按板载 A/B/X/Y/UP/DN/LF/RG，对应圆灯实时点亮，日志出现 `IN 00 xx xx ...`
6. 拖动 R/G/B 滑块（默认勾选「滑动即下发」），板载 RGB 灯实时变色；也可点预设色或「发送 RGB 到板子」
7. 勾选「彩虹渐变」可自动循环变色，用于演示

## 六之二、性能设计（长时间运行不卡）

串口/USB 上位机最常见的"用一会儿就卡"，根因都是把耗时操作放在了 GUI 线程上。本程序做了六层隔离：

| 手段 | 位置 | 说明 |
|---|---|---|
| 独立写线程 | `hiddevice.cpp::writeLoop` | `sendOutputReport()` 只入队立即返回，真正的 `HidD_SetOutputReport` / `WriteFile` 在写线程里做；GUI 线程再也不会被 USB 传输阻塞（旧版一次超时最长 1000ms） |
| 命令合并 | `hiddevice.cpp::sendOutputReport` | 队列里连续出现的 `SET_RGB` 只保留最后一帧，拖动滑块产生的上百次请求不会堆积 |
| 发送节流 | `mainwindow.cpp::queueRgb` | RGB 变化先记录到 `m_curRgb`，由 40ms 单次定时器统一发一次，最多 25 帧/秒 |
| 日志批量 flush | `mainwindow.cpp::appendLog/onFlushLog` | 日志先进内存缓冲，80ms 一次性写入 `QPlainTextEdit`；行数上限 1200，关闭折行与撤销栈 |
| 面板刷新节流 | `mainwindow.cpp::refreshUi` | 输入报告只更新统计变量并置脏标志，标签文本 20Hz 统一刷新，且内容没变就不 setText |
| 自绘色块 | `ColorSwatch` | 替代 `QLabel + setStyleSheet`，避免每秒几十次样式表重解析和控件 polish |

配套的可观测手段：日志里的 `丢帧 N` 与 `心跳 超时` 用来区分是"界面卡"还是"固件停发"。

若仍然觉得卡，先勾掉「滑动即下发」再拖滑块：这样可以判断卡顿来自下行发送还是上行解析。打开「逐帧记录」会让日志量成倍上升，调试完记得关掉。

## 七、常见问题

**① 刷新后下拉框是空的**

- 固件没烧录，或插的是只能充电的线（没有 D+/D-）
- VID/PID 不匹配：确认固件 `usb_descriptors.c` 里是 `0xCafe` / `0x4004`
- 设备被别的程序独占（BusHound、另一份上位机、串口助手），关掉再试
- 用 USBView / BusHound 确认自定义接口的 UsagePage 确实是 `0xFF00`

**② 连接失败（打不开设备）**

标准键盘/鼠标接口被 Windows 独占，本来就打不开；本程序只枚举自定义接口，正常不会碰到。若仍失败，拔插一次再刷新。

**③ 连上了但按键不动**

- 看日志有没有 `IN` 行。有 → 解析问题；没有 → 固件没上报
- 固件 `custom_scan()` 只在位图变化时发，静止时 1 秒一次心跳，属于正常
- 如果同时插着 USB 且蓝牙也在发，可能被选路逻辑压住（本项目为纯 USB 模式，不涉及）

**④ RGB 没反应**

- 确认固件 `tud_hid_set_report_cb()` 收到 `instance == 2` 且首字节是 `0x01`
- 用「原始 HEX」发 `00 01 64 00 00` 试纯红，排除滑块逻辑
- 固件里 RGB 是 0~100 百分比，发 255 会被截断到 100

**⑤ 下拉框设备名后面拖着一长串方块，窗口被撑得很宽**

`HidD_GetProductString()` 只保证写入以 `\0` 结尾的内容，缓冲区 `\0` 之后可能是残留数据。早期版本按固定 256 字符转换，把垃圾一起显示出来了。现在 `hiddevice.cpp::wideStr()` 先找 `\0` 截断、再过滤不可打印字符，`label()` 另外限长 28 字符，完整信息放在鼠标悬停的 tooltip 里 —— 重新编译即可，固件不用动。

**⑥ 板载灯亮了，上位机的圆灯不跟着变**

两个通道别混：

- 板载红/绿灯 = **系统锁定状态**，由键盘 OUT 报告（LED 字节）驱动，按电脑键盘也会亮
- 上位机 8 个圆灯 = **板载按键物理通断**，只在按下板载按键时变化

如果按**板载** X/Y 时圆灯也不亮，那是固件上报被"吃掉"了。`custom_scan()` 早期版本先改 `s_key_bitmap` 再调用 `tud_hid_n_report()`，一旦这次发送返回 false（键盘/鼠标/自定义三个 IN 端点共用 SOF，同一帧内只有第一次写 FIFO 能成功，而 `custom_scan()` 排在最后），按键变化就永久丢失，只能等 1 秒心跳，按一下就松手的按键根本看不到。现在改为**发送成功后才推进状态**，失败下一轮自动重试；并把锁定状态放进报告第 3 字节，界面新增 `CAPS / NUM` 两个徽标。
